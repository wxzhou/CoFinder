# V1.9.10 Plan

Version target: `v1.9.10`

## Goals

V1.9.10 improves three day-to-day file-management surfaces:

1. Replace modal `View Text...` and `Search Contents...` flows with a modeless tabbed content viewer window.
2. Show file-type-aware icons instead of a single blank-file glyph.
3. Add safe batch rename for local and remote selections.

## Milestone 1: Modeless Content Viewer

- Add a dedicated Electron child window loaded with `?mode=content`.
- Open it from local/remote `File Operation -> View Text...` and `Search Contents...`.
- Keep the main CoFinder window usable while the content viewer is open.
- Use tabs in the content viewer so multiple files/searches can be open at once.
- Provide less-like keyboard shortcuts and visible toolbar buttons:
  - buttons: line numbers, find, previous/next match, previous/next page, top, bottom.
  - shortcuts: `l`, `/`, `n`, `Shift+n`, `Space`, `b`, `g`, `G`, `j`, `k`, `q`.
  - no buttons for one-line scroll or closing tabs; mouse wheel and tab `x` cover those.
- Keep bounded reads for large local/remote files.
- When a search result's `View` button is clicked, open or focus a text tab at the matching line and highlight the query.
- Prefer existing local/remote `readText` and `searchText` IPC contracts where possible; add focused helper types only for content-window requests.

## Milestone 2: File-Type Icons

- Add a shared pure classifier for file visual categories.
- Use file name, extension, and entry type; do not read file contents for icon selection.
- Keep local and remote behavior identical.
- Cover common categories first: folder, symlink, text, code, document, spreadsheet, presentation, PDF, image, archive, data, executable/script, binary/unknown.
- Reuse the classifier from list/icon/column/gallery render paths so icons stay consistent.
- Preserve existing layout and selection behavior.

## Milestone 3: Batch Rename

- Add `Batch Rename...` to context menus when multiple local or remote items are selected.
- Keep single-item `Rename` as the existing inline rename flow.
- Provide an in-app preview dialog with `Original` and `New Name` columns.
- Support first-pass rules:
  - Replace Text.
  - Add Text before or after the name.
  - Format with base name, starting number, and padding.
- Protect extensions by default; include an explicit `Apply to extension` checkbox.
- Disable execution when the preview has empty names, invalid path separators/control characters, duplicate new names, or collisions with visible non-selected entries.
- Execute through existing local/remote single-item rename IPC.
- Do not attempt automatic temporary-name swapping for internal conflicts in this version.
- If execution partially fails, report completed and failed counts; do not auto-roll back.

## Documentation and Verification

- Update `CHANGELOG.md`, `README.md`, and `docs/smoke-test.md`.
- Add focused unit tests for:
  - content request routing/tab model helpers.
  - text viewer line-window/highlight helpers.
  - file icon classification.
  - batch rename rule generation and validation.
- Run focused tests after each milestone, then `npm run typecheck`, `npm test`, `npm run build`, and an Electron dev smoke.
