# CoFinder V2.7 Plan — V12 UI Refinement and Task-Center Polish

## Metadata

| Field | Value |
| --- | --- |
| **Product milestone** | V2.7 |
| **Target release** | v1.7.0 |
| **Status** | Planned |
| **Source** | Long-term UI polish roadmap after pane-scoped controls and edit-session reliability |
| **Depends on** | V2.4 pane-scoped actions; V2.5/V2.6 edit-session status surfaces |
| **Non-goals** | Broad shell rewrite; real column view unless explicitly pulled into M5; cross-platform UI |

## Goal

Make V12 feel more coherent and less prototype-like by tightening visual density, empty/loading/error states, transfer/edit task visibility, Inspector presentation, and screenshot-driven layout regression checks.

## Scope / Milestones

### M1 — Visual System Pass

- Consolidate V12 spacing, control heights, icon sizing, selection colors, and disabled states.
- Keep the product quiet and utilitarian rather than decorative.
- Avoid single-hue monotony; preserve macOS-like clarity.

**Acceptance checks**

- Toolbar, pane action strips, breadcrumbs, lists, Inspector, and drawer feel visually related.
- Text does not overlap or truncate badly in common desktop widths.

### M2 — Empty / Loading / Error States

- Add consistent pane empty states for:
  - disconnected remote;
  - empty directory;
  - permission denied;
  - lost connection;
  - loading remote listing.
- Ensure errors offer next action where possible.

**Acceptance checks**

- Remote failure states are understandable without reading logs.
- Empty directories do not look like broken panes.

### M3 — Transfer and Edit Task Center

- Upgrade the transfer drawer into a clearer task center:
  - tabs/filter chips for Running, Failed, Done, Edit Sessions;
  - retry/cancel/clear controls;
  - concise error detail copy.
- Integrate V2.6 edit session status without overwhelming normal transfer workflows.

**Acceptance checks**

- Failed transfers and failed edit uploads are easy to find.
- Clearing successful tasks does not clear unresolved edit sessions.

### M4 — Inspector Refinement

- Make Inspector denser and more scannable.
- Improve metadata grouping for local/remote parity.
- Add clearer async directory count/size states.
- Keep Inspector explicit; do not reintroduce single-click auto-open.

**Acceptance checks**

- Inspector remains useful without squeezing list unexpectedly.
- Remote async fields show loading/error/capped states clearly.

### M5 — Column View Decision Point

- Re-evaluate real column view after V2.4 removes the misleading icon.
- Either:
  - produce a V2.8/V2.9 implementation plan; or
  - explicitly defer it with rationale.
- Do not ship a half-wired toggle.

**Acceptance checks**

- Roadmap has a clear column-view decision.
- UI still contains no fake column-view affordance.

### M6 — Screenshot Regression Checks

- Add Playwright or comparable screenshot checks for key V12 states if practical.
- Cover desktop and narrower widths:
  - local/remote connected;
  - selection;
  - Inspector open;
  - transfer drawer;
  - preferences.

**Acceptance checks**

- Layout overlap regressions are easier to catch.
- Screenshot tests are stable enough not to become noise.

## Test Strategy

- Existing full gates.
- Screenshot smoke where stable.
- Manual visual review checklist with before/after screenshots.
- No behavior refactor without targeted tests.

## Risk Notes

- UI polish can sprawl. Keep each milestone visually scoped.
- Screenshot tests can be flaky; start with a small stable set.
- Do not sacrifice dense file-manager ergonomics for marketing-style visuals.
