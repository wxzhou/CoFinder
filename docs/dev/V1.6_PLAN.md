# CoFinder V1.6 Plan — Preferences MVP

## Metadata

| Field | Value |
| --- | --- |
| **Product milestone** | V1.6 |
| **Target release** | Originally planned as v0.7.0; included in v1.0.0 |
| **Status** | Implemented and included in **v1.0.0**; no standalone v0.7.0 tag |
| **Depends on** | Stable shortcut/splitter/tab/favorites (V1.3+) and transfer UX (V1.4+) so settings have meaningful surface area |
| **Non-goals** | Plugin system; full i18n; arbitrary user scripts; free-form **rsync** argument editing (no arbitrary flags unless strict allowlist) |

## Goal

Expose stable behaviors as **user preferences** without building an oversized settings application.

## Scope / milestones

### M1 — Preferences architecture

- Extend **`SettingsService`** from minimal stub toward a **versioned schema** (include **`schemaVersion`** for migrations).
- IPC remains **`{ ok, data }` / `{ ok, error }`**; renderer **never** reads/writes settings files directly.

### M2 — General preferences

- Default local starting path.
- Restore last session (define scope carefully).
- Confirm before delete (if not already global).
- Show hidden files.

### M3 — Transfer preferences

- Default **conflict policy** (align with V1.4).
- Queue auto-hide delay.
- Preserve timestamps (within rsync capability).
- **No** arbitrary rsync args unless **whitelist-only** and validated in main.

**Status:** Implemented with a strict timestamp-preservation toggle only; no free-form rsync args.

### M4 — Appearance preferences

- Compact vs comfortable row height.
- Default inspector visibility.
- Default pane ratio (coordinate with V1.3 splitter persistence).
- Sidebar visibility.

### M5 — Shortcut display

- In-app list of active shortcuts (source of truth matches implemented bindings).
- **Custom rebinding** only if cost/risk stays low—otherwise defer explicitly.

**Status:** Implemented as display-only shortcut reference. Custom rebinding is deferred.

- **`CHANGELOG.md`**: Included under the v1.0.0 release notes.
- **`docs/smoke-test.md`**: Preferences flows.

## Risk notes

- Each persisted setting is a **compatibility promise**—minimize churn; migrate carefully.
- Too many toggles increase maintenance cost; prefer defaults + a small curated set.
- Default conflict policy must stay **safe** (do not silently overwrite).
