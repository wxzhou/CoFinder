# CoFinder V2.6 Plan — Remote Edit Reliability and Session Management

## Metadata

| Field | Value |
| --- | --- |
| **Product milestone** | V2.6 |
| **Target release** | v1.6.0 |
| **Status** | Planned |
| **Source** | Follow-up hardening after V2.5 remote text edit MVP |
| **Depends on** | V2.5 edit-session model and write-back path |
| **Non-goals** | Binary/document edit sync; three-way merge; collaborative editing; remote filesystem indexing |

## Goal

Turn the V2.5 remote text edit MVP into a trustworthy daily-use workflow by adding stronger session management, safer recovery actions, clearer status, and broader regression coverage.

## Scope / Milestones

### M1 — Edit Sessions Panel

**Status:** Implemented.

- Add a dedicated panel or drawer section listing active remote edit sessions.
- Show remote path, local edit path, state, last upload time, and last error/conflict.
- Provide direct actions per session.

**Acceptance checks**

- Active edit sessions are discoverable without remembering which files are open.
- Failed/conflict sessions are visually distinct.
- Session actions are disabled when unsafe.

### M2 — Manual Session Actions

**Status:** Implemented.

- Add explicit actions:
  - Save Back Now;
  - Re-download Remote;
  - Reveal Local Copy;
  - Stop Monitoring;
  - Discard Local Copy.
- Require confirmation for destructive/discard actions.
- Preserve automatic upload as default for clean text sessions unless user pauses/stops monitoring.

**Acceptance checks**

- User can resolve failed/conflict sessions without quitting.
- Stopping monitoring does not delete unsynced edits silently.

### M3 — Watcher Robustness

- Handle atomic save patterns where editors replace the file.
- Detect deleted local edit-cache file and mark session error.
- Avoid upload loops caused by CoFinder touching metadata.
- Add capped retry/backoff for transient upload failures only when safe.

**Acceptance checks**

- TextMate/TextEdit-style saves are detected reliably.
- Deleting local edit file does not crash the app.
- Upload retry never bypasses conflict checks.

### M4 — Conflict Recovery Improvements

- Add safer conflict recovery:
  - download remote newer version beside local edited copy;
  - copy both paths to clipboard;
  - optionally open both files in editor.
- Do not implement automatic merging.

**Acceptance checks**

- User can inspect local-vs-remote conflict copies.
- CoFinder does not pick a winner automatically.

### M5 — Integration Test Harness

- Add a repeatable SFTP test fixture strategy for edit sessions.
- Use only isolated remote test roots.
- Cover happy path, conflict path, upload failure, disconnect, and app shutdown.

**Acceptance checks**

- Edit-session regressions are covered beyond manual clicking.
- Tests avoid production/user paths and do not leak credentials.

## Test Strategy

- Unit tests for watcher/session reducers.
- Integration tests using mock SFTP services where real remote is unavailable.
- Manual `sge` smoke for real server behavior under the approved test root.
- Full gates: `npm test`, `npm run typecheck`, `npm run build`, dev launch.

## Risk Notes

- Adding session UI can crowd the app; prefer compact status plus expandable detail.
- Retry/backoff must not hide persistent permission or conflict errors.
- Recovery copies may contain sensitive project data; avoid logging contents or paths beyond existing diagnostics policy.
