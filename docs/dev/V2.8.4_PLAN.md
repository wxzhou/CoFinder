# CoFinder V2.8.4 Plan — Inspector and Remote Edit Polish

| Field | Value |
| --- | --- |
| **Product milestone** | V2.8.4 |
| **Target release** | v1.8.4 |
| **Branch** | dev |
| **Scope type** | Bugfix patch after V2.8.3 / v1.8.3 |
| **Primary goal** | Polish document icons, reduce destructive toolbar risk, make folder Inspector metadata progressive, and keep completed remote-edit uploads inside the transfer surface. |

## Context

Hands-on v1.8.3 testing found four issues:

1. Document icons have rounded corners but still look too flat compared with Finder-style file icons.
2. Remote toolbar Delete and Disconnect are too close and visually similar.
3. Large folder Inspector metadata blocks while recursive size is calculated.
4. Completed remote edits leave a persistent bottom Remote edits row even after upload success.

For issue 2, the selected design is **option 4**: remove Disconnect from the remote pane toolbar and expose it from the remote title/status area instead. File operations stay in the toolbar; connection/session operations move to the status menu.

## Milestones

### M1 — Document the Patch

Status: Implemented.

Acceptance:

- Add this V2.8.4 plan before code changes.
- Record the selected Disconnect placement decision.

### M2 — Safer Remote Disconnect Placement

Status: Implemented.

Acceptance:

- Remote pane toolbar no longer contains Disconnect.
- Connected status in the remote pane title/header provides a menu with Disconnect.
- Delete remains in the file-operation toolbar and is no longer adjacent to Disconnect.

### M3 — Progressive Folder Inspector Metadata

Status: Implemented.

Acceptance:

- Selecting a folder opens Inspector quickly with immediately available metadata.
- Size / Files / Folders rows show a loading spinner while deeper metadata is still being calculated.
- Once directory metadata finishes, the same Inspector updates in place.
- Switching selection or hiding Inspector cancels or ignores stale directory metadata jobs.

### M4 — Remote Edit Upload Completion Surface

Status: Implemented.

Acceptance:

- Successful remote edit uploads do not leave a persistent Remote edits panel row.
- Upload completion is shown in the V12 transfer drawer/task surface.
- Successful remote edit completion follows the same auto-hide behavior as successful upload/download transfer rows.
- Conflict/failed/dirty/uploading remote edit sessions remain visible and actionable.

### M5 — Finder-Style Document Icon Depth

Status: Implemented.

Acceptance:

- Document icon keeps rounded page and fold corners.
- Icon gains subtle page shading, fold shadow/highlight, and bottom shadow for better Finder-like depth.
- Folder icon styling is not regressed.

### M6 — Version, Docs, and Verification

Status: Implemented.

Acceptance:

- `package.json` and lockfile are `1.8.4`.
- Update README, CHANGELOG, roadmap, and smoke-test notes for v1.8.4.
- Run `npm test`, `npm run typecheck`, and `npm run build`.

## Non-Goals

- No transfer engine changes for normal rsync upload/download.
- No changes to remote text edit conflict semantics.
- No new remote file-type support.
