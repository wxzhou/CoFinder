## Metadata

| Field | Value |
| --- | --- |
| **Product milestone** | V1.8 |
| **Target release** | v0.9.0 |
| **Status** | Planned |
| **Depends on** | Stable remote list/rename/delete baseline; transfer/conflict story mature |
| **Non-goals** | Remote edit auto-sync; remote Quick Look; complex ACL editors; remote “shell file manager” product |

## Goal

Broaden **remote file manager** operations while keeping security and clarity—**no** remote editing sync workflow.

## Scope / milestones

### M1 — Remote mkdir

- Create remote directory with validation and clear errors.

### M2 — Remote permissions basics

- Display permissions; minimal **chmod** action or dialog.
- **No** full ACL editor.

### M3 — Remote duplicate / copy path polish

- Remote **copy path** improvements.
- **Remote duplicate** only if risk is acceptable—otherwise defer with documented rationale.
- Operations executed in **main/service**, not renderer shell-outs.

### M4 — Open terminal here

- **Local**: open Terminal (or user-configured shell) at path—respect macOS conventions.
- **Remote**: optional **SSH terminal here** evaluation using profile host/user—**never** inject saved password into command lines.

### M5 — Remote symlink display

- Surface **symlink** vs file/directory in listings where SFTP allows.
- Avoid symlink cycles blowing up size calculations or navigation.

### M6 — Remote directory size

- **Async** directory size; **cancel** support; warn or cap on huge trees.
- Must not freeze UI.

## Risk notes

- Remote operations must handle **permissions**, **path normalization**, and **disconnect mid-flight**.
- **Never** concatenate renderer input into shell strings unsafely.
- Symlink and recursive size operations can be **DoS vectors**—enforce limits.
