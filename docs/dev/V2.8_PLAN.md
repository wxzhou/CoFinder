# CoFinder V2.8 Plan — Advanced Remote Navigation and Preview Decisions

## Metadata

| Field | Value |
| --- | --- |
| **Product milestone** | V2.8 |
| **Target release** | v1.8.0 |
| **Status** | Planned |
| **Source** | Long-term roadmap after remote edit and UI reliability work |
| **Depends on** | V2.7 UI refinement and column-view decision point |
| **Non-goals** | Full remote filesystem indexing by default; plugin ecosystem; cross-platform port; App Store distribution |

## Goal

Decide and implement the next meaningful navigation/preview layer after core dual-pane workflows, remote edit, and UI polish are stable.

V2.8 is intentionally a decision-heavy milestone: do not build every advanced feature. Pick the highest-value path based on V2.4-V2.7 usage feedback.

## Candidate Tracks

### Track A — Real Column View

Implement Finder-like column browsing for local and remote panes.

Candidate scope:

- Per-pane view mode state.
- Multi-column path traversal.
- Async remote column loading with cancellation.
- Keyboard navigation across columns.
- Loading/error placeholders per column.
- Preserve existing list view as default.

Use this track if users repeatedly need faster folder drilling and V2.7 confirms column view is worth the complexity.

### Track B — Remote Quick Look

Add a true-ish remote Quick Look workflow that remains distinct from remote edit.

Candidate scope:

- Space key on remote files opens temporary preview.
- Text/images first; broaden only if safe.
- Read-only cache semantics remain explicit.
- Preview lifecycle and cleanup are clear.
- Do not upload viewer edits.

Use this track if users rely heavily on previewing many remote files without editing.

### Track C — Navigation Search Upgrade

Improve navigation/search without full remote indexing.

Candidate scope:

- Current-directory fuzzy filtering.
- Better path suggestions from favorites/recents/history.
- Optional bounded recursive search under current directory with caps and cancellation.
- Remote search must be user-triggered, capped, and cancellable.

Use this track if current directory filtering becomes the limiting workflow.

## Recommended Default

Default recommendation: **Track B first, Track A second, Track C only if real usage demands it.**

Rationale:

- Remote Quick Look builds naturally on existing read-only preview work.
- Column view has high UI/state complexity and should wait until pane/action/edit states are stable.
- Recursive remote search can be expensive and surprising on shared servers.

## Scope / Milestones

### M1 — Decision Review

**Status:** Implemented. Track B — Remote Quick Look — selected in `docs/dev/V2.8_DECISION.md`.

- Review usage feedback from V2.4-V2.7.
- Choose exactly one primary track for V2.8.
- Move non-chosen tracks to future roadmap.

**Acceptance checks**

- V2.8 implementation scope is narrowed before coding.
- Non-goals are updated to avoid accidental feature creep.

### M2-M5 — Track-Specific Implementation

**Status:** Implemented for Track B Remote Quick Look.

Defined after M1 decision.

Required for any chosen track:

- isolated state model;
- cancellation/cleanup behavior;
- clear disabled/error UI;
- tests for local and remote variants where applicable;
- smoke checklist updates.

## Test Strategy

- Track-specific unit and integration tests.
- Manual SFTP smoke under approved test root only.
- Full gates: `npm test`, `npm run typecheck`, `npm run build`, dev launch.

## Risk Notes

- Advanced navigation can easily turn CoFinder into a larger IDE-like app. Preserve the personal dual-pane file-manager focus.
- Avoid background remote crawling unless explicitly requested and capped.
- Any preview/edit overlap must keep read-only and write-capable workflows visibly separate.
