# CoFinder V2.8.5 Plan — File List Columns and Tab Chrome Polish

| Field | Value |
| --- | --- |
| **Product milestone** | V2.8.5 |
| **Target release** | v1.8.5 |
| **Branch** | dev |
| **Scope type** | UI and interaction polish after V2.8.4 / v1.8.4 |
| **Primary goal** | Improve file-list data density and make the V12 tab/title chrome feel closer to a polished macOS browser-style shell. |

## Scope

1. File sizes should render with three significant digits everywhere the renderer uses `formatSize`, including Inspector and pane footer totals.
2. V12 file-list columns should be resizable by dragging column boundaries.
3. V12 file-list headers should expose a right-click column visibility menu.
4. `Name` is mandatory; `Date modified`, `Size`, `Kind`, `Permission`, and `Owner` are optional.
5. V12 tabs should align cleanly from the left, use icon buttons instead of text `x` / `+`, and have smoother Chrome-like tab contours.
6. The production window should use macOS hidden titlebar chrome so tabs live in the same visual row as the traffic lights.
7. Follow-up tab chrome correction: the first tab must start after the real macOS traffic lights, inactive tab separators should be short vertical lines, and the active tab shoulders should curve smoothly without square artifacts.
8. When optional columns make a file list wider than its pane, that pane should show its own horizontal scrollbar instead of drawing into the adjacent pane.

## Milestones

### M1 — Version and Plan

Status: Implemented.

Acceptance:

- Bump package metadata to `1.8.5`.
- Add this plan before coding.

### M2 — Size Formatting

Status: Implemented.

Acceptance:

- `formatSize` uses three significant digits for all non-zero byte values.
- Small byte values remain readable as integer `B`.

### M3 — V12 Column Model

Status: Implemented.

Acceptance:

- V12 local and remote lists share a column model with widths and visibility.
- Column widths can be dragged and are constrained to sensible minimum widths.
- Header context menu can toggle optional columns.
- `Name` is always visible and disabled in the menu.
- `Permission` and `Owner` columns are available.

### M4 — Iconized Sort and Tabs

Status: Implemented.

Acceptance:

- Sort indicators use icons instead of `^` / `v`.
- Tab close and add controls use icons instead of text glyphs.
- Tab close and add controls align on the same horizontal center.

### M5 — Browser-Style Tab Chrome

Status: Implemented; refined after visual smoke feedback.

Acceptance:

- V12 title strip visually reserves macOS traffic-light space.
- Tabs start tightly after the traffic-light cluster, with roughly one icon-width of breathing room and no overlap.
- Inactive tabs use `#F4F4F4` so the active white tab is visually clearer.
- Inactive tabs have short separators between neighbors.
- Active tabs use narrower smoother curved boundaries without square bottom protrusions.
- Tab close and add icons sit on the same horizontal centerline.
- Native app title text is hidden by Electron window chrome settings.

### M5.1 — Pane-Local Horizontal Scrolling

Status: Implemented.

Acceptance:

- File-list headers and rows share one horizontal scroll container.
- Oversized column sets stay clipped to their pane and can be inspected with a horizontal scrollbar.
- The adjacent pane is never visually covered by the current pane's file-list columns.
