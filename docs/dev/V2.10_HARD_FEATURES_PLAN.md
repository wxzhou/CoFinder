# CoFinder V2.10 / v1.9.x Hard-Feature Plan

Status: implementation branch. This document is the source of truth for the hard-feature track after the `v1.9.0` stable release.

## Release Strategy

- Development checkpoints use `v1.9.x`.
- The next public release is decided after the user has personally used the development builds for a while.
- Use `v1.10.0` if the shipped scope is mostly evolutionary and only some pillars land.
- Use `v2.0.0` if multi-lane Jobs, remote copy/move, content tools, and multiple view modes all land and feel stable as a new product generation.
- Every `v1.9.x` checkpoint must update `CHANGELOG.md` with user-visible changes, deferred work, and known risks.

## 1. Multi-Lane Jobs

### Product Goal

Long-running compression, delete, copy/move, and content-search work should not unnecessarily block unrelated transfers or each other. The UI remains one unified Jobs pane, but the scheduler can run safe work in parallel.

### Design

- Replace the current single running-task slot with lane-aware running contexts.
- Initial lanes:
  - `transfer`: upload/download, concurrency `1`.
  - `compression`: compress/decompress/MD5, default concurrency `2`, configurable `1-4`.
  - `delete`: local/remote delete, concurrency `1`.
  - `remoteMutation`: future remote copy/move, concurrency `1`.
  - `content`: grep/less-style content tools, default concurrency `1`, future configurable.
- Jobs pane remains a single list with All / Running / Failed / Done filters.
- Running count can be greater than one.
- Stop, cancel, retry, retry failed, and shutdown must address each task independently.

### Path Locks

- No two jobs may write the same destination.
- A path cannot be deleted while another job reads/writes it or any child path.
- A folder cannot be compressed, moved, or deleted while a child transfer/copy/move/content job is running.
- Remote locks include `connectionId` and normalized remote path.
- Local locks use normalized absolute local paths.
- When uncertain, keep the newer job pending or fail with a clear conflict message.

### Tests

- Transfer jobs remain serial.
- Compression jobs run up to configured concurrency.
- Transfer and compression can run concurrently.
- Delete and remote mutation lanes remain serial.
- Parent/child path locks prevent unsafe starts.
- Retry failed honors lane limits.
- Shutdown stops all running jobs.

### v1.9.2 Implementation Notes

- The unified Jobs pane is unchanged visually, but the main-process scheduler now starts safe work across lanes.
- `upload` and `download` share the serial `transfer` lane.
- `gzip`, `decompress`, and `md5` share the configurable `compression` lane.
- `delete` uses the serial `delete` lane.
- Running jobs hold local/remote path locks. Same-scope parent/child conflicts or same-destination writes keep newer jobs pending until the conflicting job finishes.
- Preferences -> Jobs exposes `Compression jobs at once` with a default of `2` and a valid range of `1-4`.

## 2. Remote Copy / Move

### Menu Placement

Remote Copy/Move are core file-management actions, closer to Rename/Delete than to utilities such as MD5 or Compress. They should be top-level selected-item remote context-menu actions:

- `Copy To...`
- `Move To...`

Place them near `Rename` and `Delete`, not under `File Operation`. Keep `File Operation` for less-common utilities: Touch, Change Timestamp, Compress, Decompress, Generate MD5, Change Permissions, Search Contents, View Text.

### Scope

- Remote selected files and folders.
- Same connection only.
- Multi-selection supported after single-selection works.
- Server-side operations only:
  - copy: prefer `cp -a` for same-server copy.
  - move: use `mv`.
- No cross-server copy/move.
- No local copy/move in the first checkpoint; Finder already covers local-only workflows.

### UX

- Dialog asks for destination remote folder or full destination path.
- Provide recent/current remote path suggestions.
- Default destination is current remote folder.
- Existing target policy:
  - Default: fail without overwrite.
  - Optional in dialog: rename/keep both for files.
  - No directory merge in first version.
- Move is destructive: require explicit confirmation for folders and multi-selection.
- Enqueue as visible Jobs tasks in `remoteMutation` lane.

### Tests

- Copy file, copy folder, move file, move folder.
- Existing target fails without overwrite.
- Quoting works for spaces, Chinese characters, and shell-sensitive names.
- Move failure preserves source.
- Copy/move jobs do not overlap unsafe delete/transfer jobs.

## 3. Grep / Less Content Tools

### Menu Placement

These are expert inspection tools, so place them under `File Operation`:

- `Search Contents...`
- `View Text...`

### Search Contents

- Scope choices: selected files, selected folder recursively, current folder.
- Remote prefers `rg`; falls back to `grep`; reports when neither is available.
- Local may use platform `rg`/`grep` or a Node fallback.
- Bound output by line count, byte count, and timeout.
- Results appear in a bottom utility panel or Jobs detail panel with file, line, preview, and Open/Edit actions.
- Never run as background indexing.

### View Text

- Read-only in-app text viewer, separate from writable remote Open/Edit.
- Local streams from disk.
- Remote streams bounded chunks on demand.
- Shortcuts: `j`, `k`, `Space`, `b`, `g`, `G`, `/`, `n`, `q`, plus native scroll.
- Do not fully download huge remote files just to render the first page.

### Tests

- Search small local/remote text fixtures.
- Output caps stop runaway search.
- Missing `rg` falls back cleanly.
- Binary-looking files are skipped or warned.
- Viewer can open first page, search within loaded content, and close without editing.

## 4. Expandable List Rows / Outline Mode

### Product Goal

Keep list view as the primary work surface, but allow folder contents to expand inline without entering the folder.

### Preference

- Add Preferences -> Appearance or Files:
  - `Show folder disclosure controls in list view`.
  - Default: off for minimal current behavior, or on only after smoke proves it does not clutter the list.

### Interaction

- Folder rows show a vector disclosure icon when enabled.
- Click disclosure icon: expand/collapse.
- Expanded children are indented and animated with a short vertical reveal.
- Disclosure icon changes between collapsed and expanded states using vector glyphs, not ASCII `>` / `v`.
- Click folder name/body: select.
- Double-click folder row: navigate into the folder.
- Nested expansion is supported.

### Data Model

- Each pane owns its expansion state independently.
- Expanded children use the same sorting and columns as the parent list.
- Remote expansion fetches children on demand and caches them per path until refresh.
- Refresh invalidates relevant expanded child caches.
- Selection and keyboard navigation operate over the flattened visible row list.
- Collapsing a folder clears selection for hidden child rows.

### Tests

- Expand/collapse local and remote folders.
- Nested expansion.
- Selection, Shift range, keyboard navigation across flattened rows.
- Refresh invalidates remote child listing.
- Filter behavior is defined and stable.

## 5. Additional Finder-Style Views

### Shared Foundation

- Add per-pane `viewMode`: `list`, `icon`, `column`, `gallery`.
- Local and remote panes choose view mode independently.
- Persist per-pane defaults in settings.
- Reuse the same selection model, context menus, drag/drop, and Jobs integration where possible.
- Avoid changing list view behavior while adding new modes.

### Icon View / v1.9.6

- Grid of file/folder icons with names.
- Good for quick visual scanning and simple selections.
- Keep metadata in Inspector rather than dense labels.
- Supports local/remote, single/multi-selection, double-click open/navigate, context menu.

### Column View / v1.9.7

- Finder-like path columns.
- Each column is a directory listing; selecting a folder opens the next column.
- Remote columns list on demand and show loading/error states.
- Keyboard navigation should feel Finder-like: left/right move across columns, up/down within a column.

### Gallery View / v1.9.8

- Preview-focused view for images/text/PDF-like files where safe.
- Reuse remote local-copy/preview guardrails.
- Large remote files require confirmation or bounded previews.
- Side strip/list preserves navigation context.

### Tests

- Per-pane independent view modes.
- View mode persists across relaunch.
- Selection and context menus work in each mode.
- Remote loading/error states do not break local pane.
- Large-folder performance remains acceptable.
