# CoFinder V2.8.8 / v1.8.8 Plan

| Field | Value |
| --- | --- |
| Product milestone | V2.8.8 |
| Target release | v1.8.8 |
| Status | Complete on dev |

## Goal

Turn the existing transfer drawer into a unified Jobs pane so upload, download, delete, and gzip work are visible, queued, cancelable where possible, and safe to leave running while the user navigates elsewhere.

## Scope

- Keep the current V12 pane/header/toolbar layout stable.
- Rename the bottom drawer from Transfers to Jobs.
- Keep upload/download behavior and conflict handling unchanged.
- Add explicit queued jobs for local delete, remote delete, local gzip, and remote gzip.
- Keep delete confirmation behavior before enqueueing destructive jobs.
- Use server-side remote delete when command execution is available, with SFTP recursion as fallback.
- Do not overwrite existing gzip targets.
- Add a Preference for whether gzip should delete the source file after successful compression; default is off.
- Preserve source files when gzip fails, regardless of the preference.
- Run remote gzip on the remote side instead of download-compress-upload.
- Show job type with icon + text: upload, download, gzip, delete.
- Preserve folder-upload child-file progress and collapsible child rows.
- Keep current queue filters working for all job kinds.
- Keep the Jobs pane top edge visually close to the v1.8.7 drawer edge and allow the expanded pane height to be resized by dragging the top edge.

## Non-Goals

- No broad UI redesign beyond the Jobs pane contents and labels.
- No parallel transfer execution.
- No exact byte progress for remote gzip/delete unless the underlying operation can report it reliably.
- No automatic retry of destructive jobs.
- No remote shell password exposure in job logs or diagnostics.

## Acceptance

- Upload/download tasks still enqueue and run serially as before.
- Confirmed local and remote deletes appear as delete jobs instead of blocking the UI until completion.
- Confirmed large/deep remote folder deletes avoid brittle recursive SFTP traversal when command execution is available.
- Confirmed local and remote gzip operations appear as gzip jobs.
- Navigating, refreshing, or selecting other files does not cancel a running delete/gzip job.
- Existing gzip target produces a failed job and does not overwrite.
- Gzip failures preserve the source file.
- The new gzip preference is visible, persists, and defaults to preserving sources.
- Remote gzip creates the `.gz` output remotely and does not download/re-upload file contents through CoFinder.
- Jobs pane shows upload/download/gzip/delete type icons and status.
- Expanded Jobs pane height can be changed by dragging the top edge, with a double-click reset.
- Completed successful jobs auto-hide using the existing queue auto-hide preference when unpinned.
- Tests and build pass.

## Verification

- `npm run typecheck`
- `npm test`
- `npm run build`
- Relevant smoke checks:
  - enqueue upload/download and confirm unchanged behavior.
  - enqueue local/remote delete and gzip from context menu.
  - create an existing `.gz` target and confirm gzip fails without overwrite.
  - enable/disable the gzip source deletion preference and confirm behavior on disposable files.
  - confirm Jobs pane filters, retry failed, clear done, pin, and auto-hide behavior.
