Fix the interaction regressions and remaining workflow friction found in **v1.1.0**. This milestone should be small, corrective, and smoke-test driven: no broad redesign unless it is required to make these operations predictable.

## Scope / Milestones

### M1 — Destructive Operation Feedback

**Status:** Implemented.

- When the user confirms delete, immediately close the confirm dialog or switch it to a disabled busy state before awaiting IPC.
- Prevent duplicate delete submissions from the same confirmation state.
- Show a non-blocking pane or queue-style busy indicator for long local/remote deletes.
- Preserve clear error surfacing if delete fails after the dialog closes.

**Acceptance checks**

- Confirming local folder delete cannot be double-clicked into duplicate delete attempts.
- Confirming remote folder delete cannot be double-clicked into duplicate delete attempts.
- Large folder delete gives visible progress/busy feedback until completion or error.
- Failed delete reports a visible pane error without reopening stale confirmation UI.

### M2 — New Folder Reliability Recheck

- Reproduce the v1.1.0 local and remote New Folder failure from toolbar and context menu.
- Verify IPC channel names, preload exposure, renderer active-pane dispatch, prompt behavior, and service errors.
- Replace `window.prompt` if it is blocked, hidden, or unreliable in Electron with an in-app create dialog.
- Add regression tests for local and remote create IPC handlers and renderer action selection where practical.

**Acceptance checks**

- Local New Folder works from toolbar and right-click menu.
- Remote New Folder works from toolbar and right-click menu after connection.
- Validation errors are visible for blank/invalid names.
- The UI refreshes and selects or at least displays the created folder.

### M3 — Default Text Editor Preference

- Add an Appearance or General preference for the default text editor used by remote text preview.
- Support at least:
  - system default text editor
  - TextEdit
  - TextMate
  - custom application name or path, if low-risk
- Remote text preview should use the configured editor for sniffed text files.
- If the configured editor cannot be opened, fall back with a visible error and a safe system default path.

**Acceptance checks**

- Setting TextMate opens sniffed remote text files with TextMate.
- Existing image preview continues to open with Preview/system image path.
- Unsupported binary files remain unsupported.
- Settings persist across relaunch.

### M4 — Inspector Reveal Semantics

- Audit every path that calls `setV12LocalInspectorReveal(true)` or `setV12RemoteInspectorReveal(true)`.
- Ensure ordinary row single-click never opens Inspector.
- `Cmd+I`, toolbar Inspector, and context-menu Show Inspector should reveal Inspector.
- Clarify or rename the existing “Show inspector by default” setting; if it causes single-click reveal, split it into explicit startup visibility versus selection-triggered reveal.
- Consider defaulting Inspector to hidden after v1.1.0 migrations if old persisted settings make the file list jump.

**Acceptance checks**

- Fresh install: single-click local or remote rows does not open Inspector.
- Existing settings with `defaultInspectorVisible` do not cause surprising single-click expansion unless explicitly intended and documented.
- Toolbar Inspector and `Cmd+I` still work.
- File list width remains stable during normal selection.

### M5 — Copy Current Path Shortcut Discoverability

- Add shortcut display to the Copy Current Path toolbar tooltip and Preferences shortcut reference.
- Keep or adjust the binding to a macOS-friendly shortcut that does not conflict with Copy Selected Paths.
- Add menu item if appropriate, so the accelerator appears in macOS menus.

**Acceptance checks**

- The user can discover the shortcut without reading source code.
- The shortcut copies the current path of the active pane.
- Copy selected path/name shortcuts keep their existing behavior.

### M6 — SSH Terminal Here Semantics

- Add pane background context menus for local and remote panes.
- For background “Open Terminal Here” / “Open SSH Terminal Here”, use the pane current directory.
- For row context menus:
  - if the selected row is a folder, open terminal in that folder;
  - if the selected row is a file, open terminal in its parent folder.
- Fix remote SSH launch so the requested path wins even when remote startup files contain `cd ...`.
- Prefer a command shape that avoids login-shell profile overrides while still leaving the user in an interactive shell, for example a non-login interactive shell after `cd` with robust POSIX quoting.

**Acceptance checks**

- Blank-area remote context menu can open SSH terminal at current remote path.
- Folder-row remote context menu opens SSH terminal inside that folder.
- File-row remote context menu opens SSH terminal in the file parent folder.
- A remote `.bash_profile` containing `cd /somewhere_else` does not override the requested Open SSH Terminal Here path.
- Local Terminal Here follows the same background/folder/file parent semantics.

## Test Strategy

- **Unit tests:** settings migration for text editor; remote shell command construction and quoting; path target selection for terminal actions.
- **Service tests:** local/remote create folder error mapping; terminal command generation with spaces/Unicode/shell-sensitive characters.
- **Renderer tests or extracted helper tests:** active-pane toolbar dispatch, context menu target resolution, Inspector reveal state transitions.
- **Manual smoke:** use isolated local temp dirs and `sge:/mnt/gpfs1/Users/zhouwenxiong/CoFinder_test` only.
- **Regression gates:** `npm test`, `npm run typecheck`, `npm run build`, `npm run check:secrets`, plus `npm run dist` before release.

## Risk Notes

- Delete progress can be expensive for recursive remote deletes; a busy state is acceptable before true item-level progress exists.
- Text editor preference must not execute arbitrary shell text. Prefer structured `open -a <AppName> <file>` or validated app paths.
- SSH terminal command generation must quote remote paths safely and must not include saved passwords.
- Background context menus must not disturb the existing selection unless the user performs a selection-changing action.
