# CoFinder V2.0.x Remote Content Tools Plan

Status: folded into the broader V2.10 hard-feature track in `docs/dev/V2.10_HARD_FEATURES_PLAN.md`. Retain this file as historical design context for grep/less content tools.

## Goal

Add explicit content-inspection tools for text-heavy local and remote workflows without turning CoFinder into a full IDE or terminal emulator.

## Planned Tools

### Grep / Search Contents

- Entry point: `File Operation -> Search Contents...` or a dedicated future search command.
- Scope options should be explicit: selected files, selected folder recursively, or current folder.
- Remote implementation should prefer server-side `rg` when available, fall back to `grep`, and report when neither is available.
- Results should be capped by line count, byte count, and elapsed time to avoid runaway jobs on shared servers.
- Results should appear in an in-app results panel with filename, line number, preview text, and open/reveal actions.
- The command must not run as background indexing or automatic crawling.

### Less / Quick Text Viewer

- Entry point: `File Operation -> View Text...` or a future viewer action, separate from writable remote `Open` / `Edit`.
- It should open an in-app read-only text viewer, likely as a Jobs pane or bottom-panel tab, rather than launching a shell `less` process directly.
- Local files can stream from disk; remote files should stream a bounded prefix first and page additional content on demand.
- Expected shortcuts: `j` / `k`, `Space`, `b`, `g`, `G`, `/`, `n`, `q`, plus native scroll.
- Large files must not be fully downloaded just to show the first page.

## Non-Goals

- No background content indexing.
- No regex builder or IDE-style project search in the first implementation.
- No remote shell embedding for arbitrary commands.
- No write/edit behavior in the less-style viewer.

## Safety Requirements

- Renderer input remains untrusted; validate paths, scope, limits, and command availability in main.
- Remote commands must be shell-quoted and scoped to the selected/current path.
- Output must be bounded and redacted where diagnostics/logs are involved.
- Search/viewer jobs should be visible and cancelable if they can run longer than a quick foreground operation.

## Open Questions

- Whether search results should live in the existing Jobs pane, a new Search tab, or a future bottom-panel multiplexer.
- Whether local grep should use a bundled JS implementation, platform `grep`, or `rg` when installed.
- How much common `less` behavior is worth reproducing before the viewer becomes too IDE-like for CoFinder's scope.
