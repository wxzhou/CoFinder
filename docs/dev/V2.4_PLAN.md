# CoFinder V2.4 Plan — Pane-Scoped Toolbar and Finder Visual Polish

## Metadata

| Field | Value |
| --- | --- |
| **Product milestone** | V2.4 |
| **Target release** | v1.4.0 |
| **Status** | Planned |
| **Source** | v1.3.0 hands-on feedback and V12 UI debt review |
| **Depends on** | v1.3.0 shipped baseline |
| **Non-goals** | Remote edit auto-sync; full remote Quick Look; implementing column view; broad shell rewrite |

## Goal

Reduce operation ambiguity in the dual-pane V12 shell and make the UI more honest and Finder-like without changing CoFinder's file-operation semantics.

## Feedback Triage

| # | Feedback | Assessment | Priority | Planned milestone |
| --- | --- | --- | --- | --- |
| 1 | The global toolbar operates on the active pane, so the user must first select a pane and then click a toolbar button. This adds a step and can cause wrong-pane operations. | Valid UX issue. Dual-pane file managers benefit from pane-scoped actions. However, duplicating the whole toolbar blindly may create clutter; commands should be split into global actions and pane-local action strips. | P0 | V2.4 M1-M3 |
| 2 | Toolbar shows List View and Column View, but only List View exists. | Valid honesty issue. An unavailable view-mode icon should not remain visible as a pseudo-feature. Implementing real column view is larger than this polish release. | P1 | V2.4 M2 |

## Product Decision

- **Adopt pane-scoped operation controls**, but not as two complete cloned global toolbars.
- Keep the top toolbar for truly global/session-level actions:
  - Back/Forward/Up/Home may remain active-pane scoped until pane chrome absorbs them.
  - Preferences, Site Manager/connect action, pane split, inspector/global layout controls remain top-level.
- Add compact **local pane action strip** and **remote pane action strip** near each pane's breadcrumb/navigation area for commands that clearly belong to one pane:
  - Local: Upload, New Folder, New Text File, Delete, Open Terminal Here, Copy Path.
  - Remote: Download, New Folder, New Text File, Delete, Open SSH Terminal Here, Disconnect, Copy Path.
- Remove or hide the Column View button until real column view is planned and implemented.
- Adjust folder icon palette toward Finder-like lighter blue, while preserving contrast in selected/inactive states.

## Scope / Milestones

### M1 — Command Ownership Audit

- Classify every current toolbar action as:
  - global/session command,
  - active-pane navigation command,
  - local-pane command,
  - remote-pane command.
- Document disabled/error states for disconnected remote pane.
- Identify duplicate context-menu commands that should share the same handler.

**Acceptance checks**

- The plan lists command ownership before UI moves.
- No destructive command loses confirmation or validation.
- Remote disconnected state has clear disabled behavior.

### M2 — Remove Misleading View Mode Controls

- Remove or hide Column View from the top toolbar.
- Keep List View only if it has useful state, or remove the view-mode group entirely if there is no user-facing mode choice.
- Update docs/smoke checklist to stop asking users to validate a nonexistent column view.

**Acceptance checks**

- No visible Column View affordance appears in V12.
- No enabled-looking toolbar control no-ops on click.
- Keyboard and existing list rendering are unchanged.

### M3 — Pane-Scoped Action Strips

- Add compact per-pane action strips in V12 pane chrome.
- Wire each button directly to that pane, without requiring prior active-pane selection.
- Keep top toolbar behavior compatible for existing shortcuts and global actions.
- Use clear tooltips/ARIA labels to distinguish local upload vs remote download.
- Preserve context-menu behavior and active-pane keyboard shortcuts.

**Acceptance checks**

- Clicking local pane Upload uploads local selection even if remote pane is active.
- Clicking remote pane Download downloads remote selection even if local pane is active.
- New Folder/New Text File/Delete operate on the pane whose strip was clicked.
- Remote strip commands are disabled or hidden clearly when disconnected.
- No extra confirmation bypass occurs for delete.

### M4 — Finder-Like Folder Icon Palette

- Update shared V12 folder icon colors for sidebar, file list, and Inspector.
- Prefer a lighter Finder-like blue with a subtle top flap and body gradient/contrast.
- Verify selected-row rendering remains legible.
- Avoid changing document/server/disk icon semantics in the same pass.

**Acceptance checks**

- Folder icons look lighter and closer to Finder's visual family.
- Sidebar and file-list folder icons remain recognizable at small sizes.
- Selected active/inactive rows keep enough contrast.

## Deferred Work

### Real Column View

Column view should be treated as a separate milestone, not a quick toggle.

Candidate future scope:

- Multi-column browser state per pane.
- Async loading and cancellation as the user drills into folders.
- Keyboard navigation across columns.
- Remote latency handling and loading placeholders.
- Separate tests for local and remote column traversal.

Recommended target: **V2.7 or later**, after pane-scoped toolbar and remote edit MVP work have settled.

## Test Strategy

- Unit/extracted helper tests for command ownership where practical.
- Existing regression gates: `npm test`, `npm run typecheck`, `npm run build`.
- Dev smoke: `npm run dev` starts cleanly.
- Manual smoke:
  - wrong-pane prevention for Upload/Download/New Folder/Delete;
  - disconnected remote pane disabled states;
  - no visible Column View affordance;
  - visual check of folder icons in sidebar, list, Inspector, selected/inactive rows.

## Risk Notes

- Duplicating controls can increase visual noise. Keep pane strips compact and icon-first.
- Moving destructive controls closer to panes must not weaken delete confirmation.
- Toolbar changes affect muscle memory; keep keyboard shortcuts stable.
- Finder-like icon polish should remain lightweight and not become a full icon system rewrite.
