# CoFinder V2.8.9 / v1.8.9 Plan

| Field | Value |
| --- | --- |
| Product milestone | V2.8.9 |
| Target release | v1.8.9 |
| Status | Complete on dev |

## Goal

Ship a focused polish milestone that keeps the V12 layout stable while updating the requested pane-toolbar icons and documenting the post-v1.8.8 reliability fixes already completed on `dev`.

## Scope

- Bump package and documentation version references to v1.8.9 for this patch milestone. The subsequent release rollup is `v1.9.0`; see `docs/dev/V2.9_RELEASE_PLAN.md`.
- Preserve the existing pane toolbar height, capsule grouping, spacing, colors, and button behavior.
- Replace only the requested toolbar glyphs:
  - Home uses a simple rounded house outline.
  - Toggle Inspector uses an eye outline.
  - Download uses an arrow-down-into-tray glyph.
  - Upload uses the same tray glyph with the arrow pointing up.
  - Delete uses a simpler trash can glyph and remains the danger-colored toolbar action.
- Keep upload/download SFTP fallback behavior for password-authenticated sites that cannot run non-interactive rsync over SSH.
- Keep the server-side remote delete path for large/deep remote folders.
- Organize Preferences into typed tabs while keeping the same settings model.
- Add lightweight stale-session handling after sleep/network resume, with lazy one-shot reconnect on the next remote action.
- Split navigation restore settings into local path on launch, local path on remote connect, and remote path on connect.
- Store per-profile local/remote path pairs from the last active tab.

## Non-Goals

- No pane layout redesign.
- No toolbar control additions or removals.
- No Jobs pane redesign.
- No transfer protocol rewrite beyond the already completed fallback behavior.
- No remote copy/move work in this milestone.
- No editable custom shortcut system; Shortcuts remains a read-only reference.

## Acceptance

- `package.json`, `package-lock.json`, README, changelog, and roadmap identify the current development version as v1.8.9 during this patch milestone. The subsequent release rollup updates them to v1.9.0.
- V12 Home, Toggle Inspector, Upload, Download, and Delete toolbar glyphs match the requested direction.
- Toolbar dimensions and action wiring remain unchanged.
- Upload/download fallback and server-side remote delete changes remain documented as part of v1.8.9.
- Preferences tabs separate General, Navigation, Jobs, Remote, Appearance, Shortcuts, and Diagnostics without changing existing setting semantics.
- Remote auto-reconnect can be toggled in Preferences and does not reconnect after explicit user Disconnect.
- When connecting to a saved profile, local and remote path restore can be enabled independently; if local restore would clear a selection or active job, it is skipped with a pane message.
- Tests and build pass.

  - Confirm the local and remote pane toolbars render with the refreshed Home, Inspector, Upload/Download, and Delete icons.

## Post-Completion Dev Adjustment

After the original V2.8.9 scope completed, remote preview/edit semantics were simplified:

- Remote context menu no longer exposes a separate **Quick Look** item.
- Remote **Open** downloads an app-managed writable local copy, opens it with the default macOS app, watches saves, and uploads changes back through the remote edit conflict checks.
- Remote **Edit** uses the same local-copy session but opens with the configured text editor. Binary-looking files require explicit confirmation before forced text-editor opening.
- Large default-app opens and executable-looking files require explicit confirmation before download/open.

After the remote operation context-menu review, selected-item utilities were expanded:

- Local and remote context menus group file utilities under **File Operation**.
- `Touch` and `Change Timestamp...` update local/remote file or folder mtimes without creating missing paths.
- `Compress` handles files as `.gz` and folders as `.tar.gz`; `Decompress` handles `.gz`, `.tar.gz`, and `.tgz`.
- `Generate MD5` creates a non-overwriting `.md5` sidecar for files and appears as a Jobs pane task.
- Future `grep` and `less` content tools are documented separately and remain unimplemented.
