# CoFinder V1.9 Plan — Packaging, Updates, and Reliability

## Metadata

| Field | Value |
| --- | --- |
| **Product milestone** | V1.9 |
| **Target release** | v0.10.0 |
| **Status** | Planned |
| **Depends on** | Feature set approaching V2.0 readiness; stable build pipeline |
| **Non-goals** | Mac App Store; enterprise MDM rollout; **telemetry on by default**; cloud account/sync |

## Goal

Make CoFinder feel like a **maintained macOS app**: repeatable releases, trustworthy diagnostics, and a clear path to updates—not only a dev-built artifact.

## Scope / milestones

### M1 — Release automation (checklists)

- Documented **version bump**, **changelog**, **git tag**, **build dmg/zip**, **smoke**, **GitHub Release artifacts** checklists (scripts optional; clarity mandatory).

### M2 — Diagnostics

- **Open log folder / log file** from UI (where safe).
- **Copy diagnostics** bundle: app version, platform, arch, **userData** path, **ssh/rsync** availability—**redact secrets**.

### M3 — First-run onboarding

- Explain **SFTP password** vs **rsync BatchMode** SSH.
- Clarify saved password scope (**browse** vs **not passed to rsync**).
- **`safeStorage`** expectations when unavailable.

### M4 — Auto-update evaluation

- Evaluate **electron-updater** + GitHub Releases (or equivalent).
- Record prerequisites: **code signing**, **notarization**, entitlement constraints.
- OK to ship **“check for updates”** entry without silent install if policy requires.

### M5 — Code signing / notarization planning

- Personal use may skip; **public distribution** requires Apple Developer ID + notarization plan—document steps and costs, no fake claims of current status.

## Acceptance checks

- `npm test`
- `npm run typecheck`
- `npm run build`
- `npm run check:secrets`
- **`docs/smoke-test.md`**: diagnostics copy (verify redaction); first-run copy review; packaged build smoke after checklist changes

## Documentation updates

- **`README.md`**: Release cadence; update policy; signing notes.
- **`CHANGELOG.md`**: v0.10.0.
- **`docs/release-checklist.md`**: Align with M1 checklists.
- **`docs/security.md`**: Diagnostics redaction rules.
- **`docs/dev/PROJECT_CONTEXT.md`**: Diagnostics IPC surface if added.

## Risk notes

- Diagnostics must **never** include plaintext passwords, keys, or host credentials.
- Auto-update must **not** corrupt **`userData`**, profiles, or encrypted credential blobs.
- Misleading signing/notarization docs are worse than absent—keep factual.
