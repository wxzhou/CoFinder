# CoFinder V1.1 Development Plan

Status: planning baseline only (no business code in this document).

## Planning Principles

- One milestone at a time.
- Keep V1 stable.
- Prefer small vertical slices (IPC + service + UI + tests) instead of large rewrites.

## M1 Rename (Local + Remote)

### Scope

- Add rename action for selected item in local pane and remote pane.
- Support single-item rename only in M1.

### Non-goals

- No multi-item batch rename.
- No advanced rename pattern rules.

### Likely Files

- `src/renderer/App.tsx`
- `src/main/ipc/channels.ts`
- `src/main/ipc/registerIpcHandlers.ts`
- `src/shared/types/ipc.ts`
- `src/main/services/LocalFileService.ts`
- `src/main/services/RemoteFileService.ts`
- tests under `tests/`

### IPC/API Design

- Add `local:rename` and `remote:rename`.
- Request shape: `{ path, newName }` (plus `connectionId` for remote).
- Response shape: `IpcResponse<{ renamed: true; newPath: string }>`

### UI Behavior

- Trigger from context menu and optional shortcut entry point.
- Prompt rename input with prefilled current name.
- On success, refresh current list and preserve selection on renamed item.

### Error Handling

- invalid input/name => `LOCAL_INVALID_INPUT` / `REMOTE_INVALID_INPUT`
- target missing => `LOCAL_NOT_FOUND` / `REMOTE_NOT_FOUND`
- permission denied => mapped permission codes
- collision => clear conflict message and stable code

### Tests

- unit tests for local/remote rename service mapping.
- IPC validation tests for empty/invalid `newName`.
- renderer integration/unit tests for rename flow state update.

### Acceptance Criteria

- Rename works for local and remote files/directories.
- No password/security regression.
- Existing browsing/selection/tab behavior unchanged.

## M2 Delete (Local + Remote)

### Scope

- Add delete action for selected entries (single + multi).
- Include confirmation modal before execution.

### Non-goals

- No recycle-bin/trash restore feature.
- No background delete queue.

### Likely Files

- `src/renderer/App.tsx`
- `src/main/ipc/channels.ts`
- `src/main/ipc/registerIpcHandlers.ts`
- `src/shared/types/ipc.ts`
- `src/main/services/LocalFileService.ts`
- `src/main/services/RemoteFileService.ts`

### IPC/API Design

- Add `local:delete` and `remote:delete`.
- Request: `{ paths: string[] }` (+ `connectionId` for remote).
- Response: `IpcResponse<{ deleted: number }>`

### UI Behavior

- Context menu delete + keyboard delete optional.
- Explicit destructive confirmation with count and names summary.
- Partial failure messaging should show which items failed.

### Error Handling

- empty path array => invalid request.
- non-existing target => stable not-found code.
- permission denied => stable permission code.
- remote disconnect mid-operation => stable remote disconnect code.

### Tests

- service tests for recursive delete/file delete mapping.
- IPC validation tests for path array and IDs.
- smoke checklist additions for confirm/cancel/partial failure.

### Acceptance Criteria

- Delete honors confirmation and does not run on cancel.
- Multi-delete reports correct result and failures.
- No V1 regressions in transfer/site manager/tab state.

## M3 Properties / Get Info

### Scope

- Add lightweight "Get Info" dialog for selected local/remote item.
- Show basic metadata: name/path/type/size/mtime/permissions/owner/group where available.

### Non-goals

- No live-updating watcher.
- No permission edit/chmod/chown.

### Likely Files

- `src/renderer/App.tsx` (or extracted dialog component)
- `src/main/ipc/channels.ts`
- `src/main/ipc/registerIpcHandlers.ts`
- `src/shared/types/ipc.ts`
- service methods in local/remote services

### IPC/API Design

- Add `local:getInfo` and `remote:getInfo`.
- Request: `{ path }` (+ `connectionId` remote).
- Response: `IpcResponse<{ info: ... }>`

### UI Behavior

- Open from context menu.
- Non-blocking modal/popover.
- Preserve current selection after close.

### Error Handling

- invalid path, not found, permission denied, disconnected mapped to stable codes.

### Tests

- service tests for metadata mapping.
- IPC validation tests.
- renderer tests for info dialog state transitions.

### Acceptance Criteria

- Accurate metadata display for both local and remote.
- No destructive side effects.

## M4 macOS-Style UI Polish A

### Scope

- Small visual consistency improvements only (spacing, typography, control alignment, hover/active clarity).
- Keep existing interaction model unchanged.

### Non-goals

- No full redesign.
- No architecture overhaul.

### Likely Files

- `src/renderer/styles.css`

- None expected.

### UI Behavior

### Error Handling

### Tests

### Acceptance Criteria

## M5 Quick Look MVP

### Scope

- Add basic preview action for local (and optionally remote cached) files for supported types.
- MVP can open system preview route instead of full in-app renderer.

### Non-goals

- No full editor.
- No binary diff or advanced media controls.

### Likely Files

- `src/renderer/App.tsx`
- local/remote context menu actions
- potential new IPC for preview helper in main

### IPC/API Design

- likely `system:quickLook` with safe path checks.
- If remote preview is included, define temporary-file flow carefully.

### UI Behavior

- Trigger via context menu and optional spacebar.
- Graceful fallback message when file type unsupported.

### Error Handling

- unsupported type, file unavailable, remote disconnected must be explicit and safe.

### Tests

- unit tests for guard/validation logic.
- smoke checklist for supported and unsupported previews.

### Acceptance Criteria

- Quick Look works for MVP scope without leaking data or breaking selection flow.

## M6 V1.1 Hardening, Docs, Release

### Scope

- Regression hardening, test expansion, docs update, packaging verification.
- Final V1.1 release checklist execution.

### Non-goals

- No new user-facing features.

### Likely Files

- `README.md`
- `docs/smoke-test.md`
- `docs/release-checklist.md`
- tests in `tests/`
- packaging config only if required for V1.1 fixes

### IPC/API Design

- contract freeze and cleanup only.

### UI Behavior

### Error Handling

- normalize remaining edge-case codes/messages.

### Tests

- run full `npm test`, `npm run build`, packaging smoke.

### Acceptance Criteria

- Release artifacts pass smoke.
- Documentation matches actual shipped behavior.

## Conflict Notes Between Current Code and V1.1 Goals

- `App.tsx` is large; adding many modal/action branches can increase risk if not split carefully.
- Remote operation coverage in service layer is currently browse-centric; rename/delete/info will expand error mapping paths significantly.
- Private key auth is currently not enabled in remote connect flow; some V1.1 UX assumptions may need explicit messaging.
- `SettingsService` is minimal; any preferences-heavy UX should avoid depending on a full settings backend before it exists.

## Recommended First Milestone

Start with **M1 Rename**.

Reason:

- smallest destructive operation with clear boundaries,
- introduces core confirmation/validation/error patterns reusable by M2/M3,
- lower risk than delete as first step.
