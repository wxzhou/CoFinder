## Context

Hands-on v1.8.1 testing found three regressions:

1. `Shift` range selection selects an unexpected deterministic set of rows in both local and remote panes.
2. `Cmd+I` does not reveal Inspector for multi-selection, while the toolbar Inspector toggle does.
3. `Cmd+I` opens Inspector for a single selection but cannot close it; the toolbar toggle can.

The likely root cause for range selection is that row-click selection uses the raw pane entry order while the UI displays filtered/sorted rows. Inspector shortcut handling also routes through a “single item info” path instead of the V12 Inspector toggle semantics.

## Milestones

### M1 — Reproduce and Pin Selection Order

Status: Planned.

Acceptance:

- Add or update tests showing that `Shift` range selection is based on the visible row order passed to the selection helper.
- Local and remote row click handlers use the same sorted/filtered row order that the user sees.

### M2 — Fix `Cmd+I` Inspector Toggle

Status: Planned.

Acceptance:

- `Cmd+I` reveals Inspector for one or more selected local files.
- `Cmd+I` reveals Inspector for one or more selected remote files when connected.
- Pressing `Cmd+I` again hides the currently revealed pane Inspector.
- Context-menu / command paths that mean “Show Inspector” still reveal Inspector without requiring exactly one selected item.

### M3 — Version and Documentation

Status: Planned.
