| Field | Value |

## Goal

Introduce a deliberately narrow and safe **Edit Remote File** workflow for sniffed text files: download to an app-managed edit cache, open in the configured text editor, monitor local saves, and upload changes back to the remote file only when conflict checks pass.

This is not an extension of read-only **Open**. It is a separate write-capable command with explicit UI state.

## Product Position

- Existing **Open** remains read-only preview/cache behavior.
- New **Edit** is opt-in, text-only, and visibly write-capable.
- CoFinder must never silently overwrite a remote file that changed after the edit session began.
- Local edited copies must survive upload failure so user work is not lost.

## Scope / Milestones

### M1 — Edit Session Model

**Status:** Implemented.

- Add an internal edit-session model keyed by tab, connection, remote path, and local edit-cache path.
- Track baseline remote metadata at open time:
  - mtime when available;
  - size;
  - optional checksum/hash only if cheap and safe.
- Keep read-only preview cache separate from edit cache.
- Add cleanup policy:
  - edit cache persists while session is active;
  - failed/dirty sessions are retained until user resolves;
  - resolved clean sessions can be cleaned on disconnect/tab close/quit.

**Acceptance checks**

- Edit session state distinguishes clean, dirty, uploading, uploaded, failed, and conflict.
- Disconnect/tab close never discards unsynced edits without visible warning.
- Read-only Open cache and Edit cache do not share mutable files.

### M2 — Edit Remote Text Entry Point

**Status:** Implemented.

- Add **Edit** to remote file context menu and pane action strip for eligible sniffed text files.
- Keep **Open** as read-only.
- Disable or reject Edit for directories, unsupported binary files, missing connection, and multi-select.
- Reuse existing text sniffing rather than extension-only checks.
- Open the edit-cache file with configured text editor.

**Acceptance checks**

- Remote text file can be opened for edit.
- Unsupported file types show a clear message and do not start edit monitoring.
- The command name and status make it obvious edits may upload to remote.

### M3 — Local Save Detection and Upload

**Status:** Implemented.

- Watch the local edit-cache file for changes.
- Debounce save events to avoid repeated uploads during editor write bursts.
- Before upload, re-stat remote file and compare with baseline/current session metadata.
- Upload through validated main-process IPC/SFTP path, not shell string composition.
- Update session baseline after successful upload.

**Acceptance checks**

- Saving a remote text edit uploads back to the same remote path.
- Rapid repeated saves do not create overlapping uploads.
- Successful upload refreshes remote pane listing when practical.

### M4 — Conflict and Failure Handling

**Status:** Implemented.

- If remote file changed since session baseline, stop upload and mark conflict.
- Preserve local edited copy and expose its path.
- Provide actions:
  - Re-download remote and discard local edit;
  - Try upload again after user confirms remote has not changed;
  - Reveal local edit copy;
  - Close session after explicit discard.
- Upload failures surface deterministic errors.

**Acceptance checks**

- Remote-changed conflict prevents overwrite.
- Local edited content remains available after conflict/upload failure.
- User can recover or discard without hidden destructive behavior.

### M5 — Minimal Edit Status UI

- Add a compact edit-session status surface:
  - active session count;
  - dirty/uploading/failed/conflict indicators;
  - current edited remote path.
- Prefer a small drawer/panel over modal interruption.
- Add status to relevant context menu/pane command states where useful.

**Acceptance checks**

- User can tell when CoFinder is monitoring an edit.
- Failed/conflict sessions remain visible until resolved.
- Closing app with dirty/failed/conflict sessions warns or blocks appropriately.

## Test Strategy

- Unit tests for session state transitions and conflict decision logic.
- Service tests for edit-cache path isolation and metadata comparison.
- IPC tests for validated upload/write-back requests.
- Manual SFTP smoke under `/mnt/gpfs1/Users/zhouwenxiong/CoFinder_test` only:
  - edit-save-upload;
  - remote-changed conflict;
  - upload failure preservation;
  - disconnect/tab close cleanup/warning.

## Risk Notes

- File watching is noisy on macOS; debounce and content comparison are necessary.
- Editors may use atomic save/rename, so watcher must handle replacement.
- This feature can overwrite remote work; conflict checks are release-blocking.
- Do not support binary/document editing until text MVP proves reliable.
