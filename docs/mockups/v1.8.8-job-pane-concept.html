CoFinder v1.8.8 Job Pane Concept

Prototype only. The current Transfer pane becomes a Job pane: upload, download, delete, and gzip jobs share one queue surface, one filter row, and one place for progress, status, retry/cancel, and diagnostics.

Job Model

  • Unified kinds: upload, download, delete, gzip.
  • Status: queued, running, done, failed, canceled, stopped.
  • Each job records source path, destination/output path, parent folder to refresh, and tab/pane origin.
  • The top edge of the Job pane is a drag handle; height is user-adjustable and should persist.
  • Completion refreshes the original parent folder only if that pane is still showing it.

Concurrency

  • Transfers remain serial by default to keep rsync behavior predictable.
  • Delete and gzip become explicit jobs with path locks, so duplicate or overlapping operations are rejected early.
  • UI navigation does not cancel jobs; jobs update the Job pane independently.
  • Upload/download can show byte progress. Delete/gzip may show stage, entries visited, PID, elapsed time, and indeterminate activity unless pre-scanned.

Remote Gzip

  • Runs remotely through SSH/SFTP job execution instead of download-compress-upload.
  • Default command behavior preserves the source and writes to a temporary output before renaming it into place.
  • If the target .gz already exists, the job fails without overwriting.
  • If compression fails, the source file remains untouched and any temporary output is cleaned up when possible.
  • Remote progress is not exact without extra tooling. CoFinder can poll PID/output size and show elapsed time rather than pretending to know a reliable percent.

Preference

Default: off. When enabled, CoFinder deletes the original only after the gzip job finishes successfully; failed jobs keep the source.
